一、系统概览

层级 技术栈 职责
Web 前端 Vue 3 + Vite + Tailwind + Element Plus 主站：上传、编辑、格式设置、预览、导出
微信小程序 原生小程序 登录、文档转换、历史、个人中心
后端 Spring Boot 3.2 + JPA + Security + JWT REST API、文档转换/导出、AI 管线
数据 SQLite (db.sqlite3) 用户、文档记录、游客、订单
部署 Docker Compose + Nginx 前端 8080、后端 8000
外部依赖 Pandoc、Apache POI、PDFBox、iText、CommonMark、Python+python-docx 格式转换与导出

七、功能清单（按模块）

1. 文档转换核心

  • 上传 Word（.docx/.doc）、PDF → Markdown
  • Pandoc 优先转换，失败回退 POI
  • 提取源文档格式（字体、段落、边距等）并回填前端
  • 保留图片到 static/media，生成可访问 URL

2. 格式设置

  • 预设：GB/T 7714、中文论文、学术、商务等（word-format-templates.json）
  • 自定义：正文/标题/页眉页脚/页码/边距/缩进/行距/列表/图表
  • 格式校验、格式摘要悬停展示
  • 从历史记录恢复格式配置

3. 预览

  • 快速预览：浏览器 HTML（marked + KaTeX + 实时 CSS）
  • 精确预览：服务端生成 PDF（static/previews）
  • 一致性自检：对比快速/精确预览差异并打分

4. 导出

  • 支持 DOCX、PDF、HTML、MD
  • 高保真：有 document_id 时用 Pandoc + 原始 Word 作参考文档
  • Pandoc 高级转换：保留表格与图片

5. 文档管理（需登录）

  • 保存文档记录
  • 导出历史列表
  • 删除记录
  • 下载 original / processed / styled
  • 独立预览页 /preview/:documentId

6. 用户体系

  • 注册 / 登录（JWT）
  • 游客（设备指纹 + 配额）
  • 微信登录（服务层已实现，需配置 WECHAT_APP_ID/SECRET）
  • 会员字段：VIP、次数包、会员类型（数据层就绪）

7. AI 增强（可选，llm.enabled=false 默认关闭）

  • 文档 → IR 中间表示
  • 自然语言 → 样式配置
  • python-docx 代码生成 + 执行
  • 一站式生成 Word

8. 其他

  • 图片提取与浏览
  • 文档元素分析
  • 反馈表单 UI（后端 API 待实现）
  • 会员权益 UI（后端 API 待实现）
  • Docker 一键部署、Actuator 监控、OpenAPI 文档

十、总结

Transfer Words 的核心价值是：把 Word/PDF 转为可编辑的 Markdown，在 Web 端配置学术/公文等版式，再通过 Pandoc/POI/iText 导出为高保真 Word 或 PDF；并可选走 AI 管线（IR → 样式 → python-docx）做智能排版。

当前实现最完整的是 文档转换主链路；会员支付、反馈、部分配额接口 在前端已有调用，后端 Controller 尚未落地，分析时按「预留功能」理解即可。

如需针对某一模块（例如仅 AI 管线、仅 Pandoc 导出、或微信小程序流程）单独拆成更细的时序图，可以说明要聚焦的部分。
